# OpenStarry Code 0.5.9

Release date: 2026-08-17

OpenStarry Code 0.5.9 improves mixed-provider fusion routing, restores network
and filesystem behavior on Windows hosts with unavailable sandbox backends,
ships the expanded bundled skills and reverse-engineering tool catalog, and
repairs real-time external-channel progress and QQ rich-media delivery.

## Highlights

- Custom B5 fusion now derives request limits from each member's own endpoint
  and model metadata instead of reusing the top-level provider budget.
- Versioned OpenAI-compatible base URLs no longer become duplicate paths such
  as `/v1/v1/models`, and model discovery preserves the configured custom
  provider slot so independent API keys expose their own model IDs.
- Aggregator requests can omit oversized tool schemas while retaining candidate
  synthesis, retry transient upstream failures without duplicating partial
  output, and fall back cleanly after a no-output aggregator outage.
- Proposer progress remains live while quorum collection is running, including
  explicit finish/error events for failed or cancelled candidates.
- External channels now receive public reasoning, intermediate narration, tool
  activity, provider status, router decisions, and fusion progress while a turn
  is running. Process updates and the final answer are delivered separately so
  append-only channels do not repeat the full programming trace at completion.
- QQ group and C2C replies now upload generated local artifacts through the
  official `upload_prepare` / part PUT / `upload_part_finish` / `files` flow,
  then send `msg_type=7` media with the triggering `msg_id` and monotonic
  `msg_seq`. URL media remains available for proactive sends.
- The `message` tool, heartbeat delivery, and scheduler delivery now construct
  explicit QQ `chat_type` and OpenID routes; proactive sends no longer mistake
  a destination OpenID for a passive reply message ID.
- Full-mode agents with `sessions_spawn` and `sessions_yield` now proactively
  split projects containing multiple independent substantial workstreams,
  report child status, retry one narrowed failed delegation, and perform an
  integrated parent verification before finishing.
- Durable Goals and the bundled `application-build` workflow remain available
  for long-running project work across reconnects.
- Full Host Access now bypasses in-process network sandbox gates as intended.
  Public-domain DNS poisoning can be recovered through validated public DNS
  answers, while HTTP connections remain pinned to the vetted public address.
- Read-only filesystem tools continue operating when the Windows sandbox
  backend is unavailable; workspace and guest restrictions remain enforced by
  their request contexts.
- The Skills view retries the brief empty-catalog window during gateway startup,
  and `skills.list` / `skills.status` can run as concurrent read-only RPCs.
- Bundled skill discovery now supports nested packs, up to 1000 bundled skills,
  replacement decoding for malformed third-party UTF-8, dependency inspection,
  provenance labels, notices, references, and packaged support files.
- The release contains 637 bundled skill manifests plus tool scripts, including
  Java/JAR/EXE reverse orchestration, Android workflows, Ghidra/IDA integration,
  native-residue triage, and VMP 3.x deobfuscation guidance.

The GitHub release workflow builds the versioned Python artifacts, macOS
Electron assets, Windows NSIS/MSI installers, updater metadata, and checksums
from tag `v0.5.9`.

Windows installers are currently unsigned. Verify downloaded files against
`SHA256SUMS` before deployment.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback. Use either MSI or NSIS consistently on a given machine rather
than installing both formats to separate destinations.

## Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or:

```toml
[privacy]
disable_network_observability = true
```

The legacy `OPENSTARRY_CODE_TELEMETRY_DISABLED=true` and
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` controls remain supported.
