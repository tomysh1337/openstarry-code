# OpenStarry Code 0.5.7

Release date: 2026-08-16

OpenStarry Code 0.5.7 makes custom-provider model selection resilient when a
compatible endpoint cannot serve its live model catalog. The saved model stays
available, while the interface keeps the real transport failure visible instead
of presenting the model as missing or unrecognized.

## Highlights

- A failed live model refresh now falls back to the model stored in the active
  provider profile with explicit `configured` provenance.
- DNS, TLS, timeout, and connection failures retain the
  `transport_transient` classification and show a network-oriented diagnostic.
- A later successful refresh replaces the configured fallback with the real
  live catalog.
- `custom`, `custom_2`, `custom_3`, and `custom_4` remain independent Chat
  Completions deployments. Each slot can use its own credential environment
  variable, Base URL, proxy, request headers, and model.
- Windows release artifacts include the pinned Codex-X companion runtime after
  the release-bundle correction on main.
- Durable Goals and the bundled `application-build` workflow remain available.

Personal API keys and local provider profiles are not embedded in release
artifacts. Only generic provider and fallback behavior ships in this version.

## Model Discovery Behavior

1. OpenStarry Code requests the provider's live model catalog.
2. A successful live response replaces any configured fallback rows.
3. A failed response preserves the saved model in the picker and retains the
   discovery failure kind for diagnosis.
4. An empty profile model still produces no synthetic option; free-form model
   entry remains available.

The fallback is intentionally limited to the current profile. Switching
between custom slots cannot copy or reuse another slot's model identity.

## Upgrade Notes

No configuration schema migration is required. Existing provider profiles keep
their endpoint, credential source, and saved model. The new fallback behavior
is applied when the Control UI refreshes a catalog.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback. Use either MSI or NSIS consistently on a given machine rather
than installing both formats to separate destinations.

## Network Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or in configuration:

```toml
[privacy]
disable_network_observability = true
```

`OPENSTARRY_CODE_TELEMETRY_DISABLED=true` disables installation telemetry.
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` disables passive update checks.
