# OpenStarry Code 0.5.5

Release date: 2026-08-14

OpenStarry Code 0.5.5 adds operator-defined model protocols and Chinese-web
search providers, completes the user-facing product identity, and fixes an
invalid HTTP correlation-header rename found during release verification.

## Highlights

- The desktop app now uses an original OpenStarry starfield icon across
  Windows and macOS package surfaces.
- Custom API setup now exposes verified Chat Completions, OpenAI Responses,
  and Anthropic Messages choices directly after TokenRhythm.
- Bing China, Baidu, and Sogou join DuckDuckGo as key-free web search sources.
- Search sources share normalized results, runtime diagnostics, fallback
  behavior, proxy settings, and sandbox domain grants.
- Current UI, CLI guidance, update links, release links, and provider
  attribution use OpenStarry Code naming.
- Legacy storage keys, IPC names, and migration paths remain readable so an
  existing profile can upgrade without losing settings.
- Durable Goals, reconnect-safe sessions, the bundled `application-build`
  workflow, and packaged MSI/NSIS distribution remain available.

## Custom APIs

The first-run provider catalog now prioritizes:

| Provider ID | Protocol | Credential variable |
| --- | --- | --- |
| `custom` | OpenAI Chat Completions | `CUSTOM_LLM_API_KEY` |
| `custom_responses` | OpenAI Responses | `CUSTOM_RESPONSES_API_KEY` |
| `custom_anthropic` | Anthropic Messages | `CUSTOM_ANTHROPIC_API_KEY` |

All three require a Base URL and model ID. Credentials are optional for local
or externally authenticated gateways. Chat Completions and Responses endpoints
can populate the model picker from a live model catalog; manual model IDs remain
available when discovery is unsupported.

## Search Providers

The no-key catalog now includes:

- `duckduckgo`
- `bing_cn`
- `baidu`
- `sogou`

Sogou uses the mobile result endpoint because its desktop endpoint currently
redirects ordinary automated requests to an anti-spider page. The runtime
detects provider challenge pages and returns a structured provider error.

## Fixes

- Correlation headers now use the legal `X-OpenStarry-Code-*` prefix. The
  previous renamed prefix contained a space and could fail before a request
  reached the provider.
- Electron first-run tests and runtime paths agree on
  `openstarry-code/config.toml`.
- The frozen desktop gateway resolves its bundled migrations from
  `openstarry_code/_migrations` and starts without a source checkout.
- The packaged first-send gate now applies the renamed OpenStarry Code context
  and test environment variables and captures renderer state on failure.
- Fresh Control UI startup admits the complete advertised set of concurrent
  optional metadata reads, avoiding a bootstrap-time `sessions.list` rejection.
- Update checks and provider attribution send OpenStarry Code identifiers and
  link to this repository's releases.

## Upgrade Notes

No configuration migration is required. Existing legacy keys and profile
locations remain supported for import and continuity. New profiles use the
OpenStarry Code directories and CLI naming.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback. Use either MSI or NSIS consistently on a given machine rather
than installing both formats to separate destinations.

## Network Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or in configuration:

```toml
[privacy]
disable_network_observability = true
```

`OPENSTARRY_CODE_TELEMETRY_DISABLED=true` disables installation telemetry.
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` disables passive update checks.
