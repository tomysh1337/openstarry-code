# OpenStarry Code 0.5.6

Release date: 2026-08-15

OpenStarry Code 0.5.6 makes third-party model endpoints easier to configure,
duplicate, inspect, and operate. Custom Header support now follows every request
path while keeping secret values out of public state and diagnostics. Windows
Desktop also includes Codex-X and mounts the user's Codex Skills as a live
catalog layer.

## Highlights

- The setup catalog has a dedicated Third-party APIs group.
- Custom providers open in a focused editor with provider metadata, credentials,
  endpoint controls, connection testing, proxy settings, and custom Headers.
- Protocol badges distinguish OpenAI Chat Completions, OpenAI Responses, and
  Anthropic Messages before a provider is selected.
- Four independent Chat Completions slots remain available alongside dedicated
  Responses and Anthropic endpoints.
- Custom request headers work in probes, model discovery, runtime turns,
  Router/Ensemble execution, automatic naming, and context compaction.
- Chat Completions profiles can be copied atomically into the next empty custom
  slot without exposing credentials or Header values to the browser.
- Windows installers bundle the pinned Codex-X `v0.3.12` portable runtime. The
  Skills toolbar opens it with a shared `CODEX_HOME`, so prompts,
  conversations, Skills, and MCP configuration use the same Codex data.
- `${CODEX_HOME:-~/.codex}/skills` is loaded as a dedicated `codex` layer and
  refreshes without maintaining a copied 18 MB catalog.
- The read-only `sandbox_status` model tool exposes the active backend, setup
  status, capability probe, and effective file/network posture.
- Durable Goals and the bundled `application-build` release workflow remain
  available.

## Third-party APIs

| Provider ID | Protocol | Purpose |
| --- | --- | --- |
| `custom` | OpenAI Chat Completions | Primary compatible endpoint |
| `custom_2` | OpenAI Chat Completions | Independent compatible slot |
| `custom_3` | OpenAI Chat Completions | Independent compatible slot |
| `custom_4` | OpenAI Chat Completions | Independent compatible slot |
| `custom_responses` | OpenAI Responses | Responses-native endpoint |
| `custom_anthropic` | Anthropic Messages | Messages-native endpoint |

Each profile keeps its own Base URL, credential, model, proxy, and custom
headers. Supported endpoints can populate the model picker from their live
catalog; manual model IDs remain available when discovery is unsupported.

## Custom Header Handling

- Header names are retained while values are redacted from public
  configuration, RPC responses, object representations, and LLM traces.
- Authentication and HTTP framing headers are reserved. Names are unique
  without regard to case, and CR, LF, and NUL characters are rejected.
- Editing a profile on the same origin can preserve masked values. Changing the
  Base URL to another origin clears old headers and requires fresh values.
- A server-side duplicate operation copies a Chat Completions profile into the
  next empty slot atomically without returning secrets to the renderer.

## Codex-X and Shared Codex Data

The Windows desktop package downloads Codex-X only during the release build,
pins it to `v0.3.12`, and verifies the portable archive against SHA-256
`3641a3cc4434fd8bf237108ccb7177c231606639b4990b32630faccee403978f`.
The verified runtime, portable marker, upstream README, machine-readable
manifest, and MIT license are then included in the EXE and MSI packages.

OpenStarry Code launches Codex-X with the current `CODEX_HOME`, falling back to
`~/.codex`. This is the shared source for Codex prompts, conversation indexes,
Skills, and MCP configuration. Codex-X's own database and UI settings use a
separate `CODEXX_HOME` under the OpenStarry desktop profile. Microsoft Edge
WebView2 Runtime is required by the bundled Codex-X application.

## Upgrade Notes

No configuration migration is required. Existing provider profiles continue to
load, and profiles without custom headers keep their previous behavior.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback. Use either MSI or NSIS consistently on a given machine rather
than installing both formats to separate destinations.

## Network Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or in configuration:

```toml
[privacy]
disable_network_observability = true
```

`OPENSTARRY_CODE_TELEMETRY_DISABLED=true` disables installation telemetry.
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` disables passive update checks.
