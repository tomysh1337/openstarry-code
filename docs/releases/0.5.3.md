# OpenStarry Code 0.5.3

Release date: 2026-08-14

OpenStarry Code 0.5.3 is the first source-first release under the renamed
project identity. It combines the upstream 0.5 runtime with a stackable custom
API mesh, automatic model discovery, and a fully renamed Python, Web UI,
desktop-source, configuration, and release surface.

## Highlights

- Four isolated OpenAI-compatible slots: `custom`, `custom_2`, `custom_3`, and
  `custom_4`.
- Automatic `/models` discovery with manual model-ID fallback.
- The `custom_b5` ensemble can compare and aggregate several configured APIs.
- Durable Goals, queued follow-ups, session forks, and reconnect-safe long
  running tasks.
- Expanded Skills, scheduling, recovery, sandbox, provider, and diagnostics
  workflows.
- Web UI dependency audit reports zero known vulnerabilities.

## Renamed surfaces

| Surface | Name |
| --- | --- |
| Repository | `openstarry-code` |
| Python distribution and CLI | `openstarry-code` |
| Python import and source package | `openstarry_code` / `src/openstarry_code` |
| Web UI directory | `openstarry-code-webui` |
| TUI host | `openstarry-code-tui-host` |
| Configuration | `openstarry-code.toml` / `~/.openstarry-code/config.toml` |
| Environment prefix | `OPENSTARRY_CODE_*` |

The Python import uses an underscore because Python identifiers do not support
hyphens. Existing `.opensquilla` state and `OPENSQUILLA_*` settings are read
only where the migration layer needs them to import an older profile.

## Runtime and UI changes

- Custom provider slots keep independent base URLs, credentials, model IDs,
  and proxy settings.
- Successful connection probes expose discovered model IDs in the control UI.
- Long-running streams recover more cleanly after renderer reconnects and
  temporary provider activity gaps.
- Community Skills use immutable source resolution and transactional lifecycle
  management.
- TokenRhythm discovery merges published catalog metadata with credential
  entitlements and bounds fallback output limits.
- Recovery preserves chats, Agents, memory, and scheduled jobs while repairing
  recoverable configuration failures.
- Desktop TypeScript compilation, icon validation, and deep-link handling use
  the OpenStarry Code identity and `openstarry-code://` protocol.

## Fixes and dependency updates

- Updated DOMPurify to 3.4.13 and Nano ID to 3.3.18.
- Updated Electron dependency resolutions for `fast-uri`, `js-yaml`, and
  `undici`; the desktop dependency audit reports zero known vulnerabilities.
- Fixed release packaging paths so the wheel contains `openstarry_code` and
  the compiled Web UI artifact.
- Excluded local dependency trees and nested build artifacts from the source
  distribution, reducing it from 127 MB to about 19 MB.
- Fixed source, Docker, service-unit, Homebrew, portable installer, and CI paths
  after the namespace migration.
- Preserved old profile discovery as an explicit one-time migration boundary.

## Upgrade notes

Back up the active profile before upgrading. Install 0.5.3 over the existing
environment, then start `openstarry-code`. The migration layer imports legacy
profile data into `~/.openstarry-code` and leaves the source profile available
for rollback.

```sh
openstarry-code onboard --if-needed
openstarry-code gateway run
```

## Network privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or in configuration:

```toml
[privacy]
disable_network_observability = true
```

`OPENSTARRY_CODE_TELEMETRY_DISABLED=true` disables installation telemetry, and
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` disables passive update checks.
