# OpenStarry Code 0.5.4

Release date: 2026-08-14

OpenStarry Code 0.5.4 adds the first verified Windows desktop distribution for
the renamed project. The application is available as both an interactive NSIS
EXE and a WiX MSI package, with the Python gateway and pinned developer
runtimes included.

## Highlights

- Windows x64 NSIS EXE and WiX MSI installers.
- Bundled Python 3.13, Node.js 24, and PortableGit runtimes.
- Bundled PyInstaller gateway with the Router V4 inference assets and compiled
  Web UI.
- New `application-build` skill for repeatable application packaging and
  release operations.
- Runtime extraction works with GNU tar and Windows bsdtar.
- Durable Goals, queued follow-ups, reconnect-safe sessions, custom API slots,
  automatic model discovery, and the B5 ensemble remain available from 0.5.3.

- `SHA256SUMS`

The EXE uses NSIS and allows the destination directory to be selected. The MSI
uses WiX, installs per user, and creates desktop and Start Menu shortcuts. Both
formats use product name `OpenStarry Code`, app ID `code.openstarry.desktop`,
and protocol `openstarry-code://`.

Windows installers are currently unsigned. Verify the downloaded bytes against
`SHA256SUMS` and review the
[code-signing policy](../code-signing-policy.md) before deployment.

Install the Python wheel separately with:

```sh
uv tool install --python 3.12 \
  "openstarry-code[recommended] @ https://github.com/tomysh1337/openstarry-code/releases/download/v0.5.4/openstarry_code-0.5.4-py3-none-any.whl"
```

## Application build skill

The bundled `application-build` skill records the supported Windows build
sequence:

```powershell
Set-Location desktop/electron
npm.cmd ci
$env:NODE_OPTIONS = '--use-system-ca'
npm.cmd run fetch:runtimes
npm.cmd run build:gateway
npm.cmd run dist:windows
```

`dist:windows` compiles the Electron main process, builds MSI and NSIS targets,
and finishes with icon and package-layout verification.

## Fixes

- `fetch-bundled-runtimes.mjs` probes `tar --help` before passing
  `--force-local`. Windows bsdtar now receives the portable `-xf` argument set.
- PowerShell ZIP extraction uses `OPENSTARRY_CODE_RUNTIME_ARCHIVE` and
  `OPENSTARRY_CODE_RUNTIME_DESTINATION`.
- The local editable environment is synchronized to the current
  `openstarry-code` checkout rather than the deleted pre-rename directory.
- Git LFS Router V4 assets are required and size-checked before the gateway can
  be frozen, preventing a reduced-function desktop package.

## Upgrade notes

Back up the active profile before upgrading. Install 0.5.4 over the existing
desktop application. The migration layer imports legacy profile data into
`~/.openstarry-code` and leaves the source profile available
for rollback.

The MSI and NSIS packages share the same application identity. Use one package
format consistently for managed deployment; do not install both formats into
different destinations on the same profile.

## Network privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or in configuration:

```toml
[privacy]
disable_network_observability = true
```

`OPENSTARRY_CODE_TELEMETRY_DISABLED=true` disables installation telemetry, and
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` disables passive update checks.
