# OpenStarry Code 0.6.2

Release date: 2026-08-29

OpenStarry Code 0.6.2 completes cross-platform desktop packaging: in addition
to the existing Windows and macOS installers, the release now ships native
Linux packages (AppImage and DEB) built from the same verified Web UI and
Python runtime.

## Highlights

- Linux desktop installers are now produced as part of the release workflow:
  an AppImage (single-file, no installation required) and a Debian `.deb`
  package for apt-based distributions.
- The bundled Python and Node runtimes for `linux-x64` are fetched and
  verified before packaging, matching the runtime contract used on Windows and
  macOS.
- The release workflow gate now validates the complete cross-platform asset
  set (Windows, macOS, and Linux) and regenerates `SHA256SUMS` across every
  desktop artifact before upload.
- All previously released features and workflow stages remain available:
  remote file browsing, real-time command mirroring, computer-use, session
  recovery, durable Goals, the bundled `application-build` workflow, and the
  migration layer for legacy data.

## Verification

- Backend gateway and remote route suites pass.
- Web UI builds pass `vue-tsc`, the architecture guard, and i18n checks; the
  verified `dist` is written into the gateway static directory.
- Electron packages are verified per platform, including the bundled runtime
  and generated bundle checks for `linux-unpacked`.
- No configured API key is embedded in source or release notes.

The GitHub release workflow builds the versioned Python artifacts and the
Windows NSIS/MSI, macOS DMG/ZIP, and Linux AppImage/DEB installers from tag
`v0.6.2`.

Windows and Linux installers are currently unsigned. On Linux, make the
AppImage executable before running it:

```sh
chmod +x OpenStarry-Code-0.6.2-linux-x64.AppImage
./OpenStarry-Code-0.6.2-linux-x64.AppImage
```

Verify downloaded files against `SHA256SUMS` before deployment.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback.

## Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or:

```toml
[privacy]
disable_network_observability = true
```

The legacy `OPENSTARRY_CODE_TELEMETRY_DISABLED=true` and
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` controls remain supported.
