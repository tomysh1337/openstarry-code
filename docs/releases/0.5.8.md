# OpenStarry Code 0.5.8

Release date: 2026-08-16

OpenStarry Code 0.5.8 fixes remote custom-provider requests being treated as
local 8192-token deployments and adds the desktop integration controls shown
in the updated settings surface.

## Highlights

- Remote `custom`, `custom_2`, `custom_3`, and `custom_4` endpoints use a
  131072-token compatibility context when the provider does not publish model
  limits. Explicit per-model overrides and live metadata remain authoritative.
- Loopback and localhost endpoints continue using the conservative 8192-token
  local default.
- Live discovery keeps the provider's real model ids with independent custom
  slots and credentials.
- Settings now include computer-control targets, browser enablement and URL
  actions, browser-data cleanup, and coding integrations for hooks, connections,
  Git, environment variables, and worktrees.
- Durable Goals and the bundled `application-build` workflow remain available.
- Durable Goals continue across reconnects while the provider/model fixes are
  applied without changing existing conversation data.

## Verification

- Provider catalog, resolution, shared-catalog, and capability parity tests:
  68 passed.
- Web UI unit, architecture, type, localization, and production-build checks
  passed.
- Packaged Windows gateway smoke check passed on the installed E: drive copy:
  `/healthz`, `/readyz`, `/control/`, and live `custom_2` model discovery.
- `config.effective` reports `131072` for the configured remote custom endpoint;
  no API key is embedded in source or release artifacts.

`SHA256SUMS` for tag `v0.5.8`.

Windows installers are currently unsigned. Verify downloaded files against
`SHA256SUMS` before deployment.

Back up the active profile before upgrading. Install over the existing desktop
application; the migration layer imports legacy data and leaves the source profile available
for rollback. Use either MSI or NSIS consistently on a given machine rather
than installing both formats to separate destinations.

## Privacy

Disable non-user-initiated network observability with:

```sh
OPENSTARRY_CODE_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true
```

or:

```toml
[privacy]
disable_network_observability = true
```

The legacy `OPENSTARRY_CODE_TELEMETRY_DISABLED=true` and
`OPENSTARRY_CODE_UPDATE_CHECK_DISABLED=true` controls remain supported.
