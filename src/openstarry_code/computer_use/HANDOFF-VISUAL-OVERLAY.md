# HANDOFF — 电脑使用可视化层（重写）

> 版本：v2（2026-08） · 状态：已实施 · 涉及模块：`cursor_overlay.py`
> 本文件记录用户反馈的问题、根因，以及新架构的设计决策，供后续迭代参照。

## 1. 用户诉求（原文提炼）

1. 泛光**变成了黑色**，观感像没渲染好，整体很生硬；
2. 打字时**右下角出现黑框**；
3. 顶部「Starry 正在使用你的电脑」横幅**从屏幕外直接跳入，没有动画**；
4. 横幅要的是**毛玻璃**效果；
5. 边框要**真渐变**（浅蓝→粉，用户自定义主题色）；
6. 光标（Win11 真实光标图形）尺寸要对；
7. 要求产出一份 handoff 文档，把诉求与方案固化下来。

## 2. 根因分析（旧实现为什么失败）

| 症状 | 根因 |
|---|---|
| 泛光发黑 | Tk `-transparentcolor` 只能让**完全等于键色**的像素透明。渐变向键色混合后的中间色带既不是透明、也不是键色，被原样画成暗色条纹。Tk Canvas 无法表达「逐像素 alpha 渐变」 |
| 黑框 | Tk Toplevel/Canvas 窗口在显示前透明度属性未完全生效时的瞬时全黑闪帧（busy spinner / 光标窗口） |
| 横幅跳入 | 旧代码 `_slide` 依赖 `after` 回调步进，且仅有 10 步 × 30ms 粗粒度；此前还发现过 `after` 未泵事件循环导致动画完全不跑 |
| 无毛玻璃 | `SetWindowCompositionAttribute` acrylic 需要 DWM 合成窗口；Tk 窗口 + `-alpha` 的组合拿不到 acrylic，静默回退成了纯色块 |

**结论：Tk 方案在 Win11 上无法满足需求，废弃，整体重写。**

## 3. 新架构（v2，已实施）

**核心：单一 Win32 layered 窗口 + PIL 逐像素 RGBA 渲染。**

```
CursorOverlay (线程安全门面, queue)
  └─ 渲染线程
       ├─ Win32 窗口: WS_EX_LAYERED|TOPMOST|TOOLWINDOW|NOACTIVATE
       │   WM_NCHITTEST→HTTRANSPARENT（鼠标穿透，无 WS_EX_TRANSPARENT，避免合成性能损失）
       ├─ 帧循环: 16ms tick + 消息驱动即时渲染
       ├─ 渲染管线（全在预乘 alpha 域，RGBa）
       │    scene = glow呼吸混合（静态缓存 premul）
       │    frame = scene.copy → add(横幅层区域) → add(光标层区域)
       │    → tobytes("raw","BGRA") → UpdateLayeredWindow(ULW_ALPHA)
       └─ DIB: CreateDIBSection 32bpp top-down（biHeight 为负）
```

### 3.1 泛光（真渐变 + 真透明）

- 四条边各 28px 厚，**颜色沿周长从 accent 流向 accent2**（每边 64 段、段间线性插值），四角颜色无缝衔接；
- 每条边**向内逐像素 alpha 衰减**（`(1-i/T)^1.6` 幂衰减，柔和溶解）——这是逐像素 alpha，**物理上不可能发黑**；
- 呼吸动画 = 高/低两档亮度缓存图 `Image.blend` 交叉淡入淡出（周期 3.4s）；
- `accent2` 缺省 = accent 向**白色**混合 50%（浅色主题下即「白→浅蓝」效果）。

### 3.2 毛玻璃横幅（真·模拟毛玻璃）

`SetWindowCompositionAttribute` 对 layered 窗口不生效，改用**等价视觉**：

1. `ImageGrab.grab(all_screens=True)` 桌面截图（session_start 时一次性）；
2. 裁剪横幅落位区域 → `GaussianBlur(18)` 背景透过糊镜；
3. 主题调光：深色压暗 0.92 / 浅色提亮 1.06 + 主题色罩 45–55%；
4. 圆角 18px 遮罩 + 1px 半透明描边 + 柔和投影；
5. 星形图标 + 微软雅黑文字（`msyh.ttc`）。

效果 = 背景内容实时透过毛玻璃，AV 上与 acrylic 一致，且**不受 DWM/系统版本影响**。

### 3.3 动画规范（全部缓动，杜绝跳变）

| 动画 | 时长 | 缓动 |
|---|---|---|
| 横幅滑入 | 520ms | easeOutCubic（快→慢，从屏外 -h-12 滑到顶部 14px） |
| 横幅透明度渐入 | 400ms | easeOutQuad |
| 横幅退出 | 300ms | easeInCubic + alpha 渐出 |
| 泛光呼吸 | 3.4s/周期 | sin 交叉淡入 |
| 点击涟漪 | ~480ms | easeOutCubic 扩散 + 淡出 |
| 光标隐藏 | 空闲 800ms 后 | 200ms fade |
| busy 转圈 | 90ms/步 | 匀速弧段 |

### 3.4 光标（Win11 真实图形）

- `.cur` 手工解析器保留（`_load_cur_rgba`，PIL 会丢 alpha，必须自解 ICO 容器）；
- 32px 帧 + hotspot(14,14)：箭头尖端精确落在控制器坐标；
- 按下切换 `link.cur`（手型）、释放时触发涟漪；AI 打字/长动作时淡色罩 + 转圈。

### 3.5 稳健性（Cosmetic 黄金法则）

- 渲染层任何异常**只降级不抛错**：窗口创建失败 → 门面标记 broken，后续调用全部静默跳过；
- 多显示器：窗口覆盖整个虚拟屏（`SM_XVIRTUALSCREEN`…），坐标 = 全局 - 虚拟原点；
- 截图尺寸与虚拟屏不符（极端多屏布局）→ 自动退回主屏模式。

## 4. 接口契约（不变，上游无感）

```python
CursorOverlay()                                # 线程安全门面
  .session_start(theme=..., accent=..., accent2=...)   # 开始会话（横幅+泛光+待命光标）
  .show(x, y, STATE_IDLE | STATE_PRESSED)      # 光标状态/涟漪
  .move(x, y) / .hide() / .set_busy(bool)
  .session_end()                               # 全部退场（含 Esc 中止）
  .close() / .is_available()
```

controller.py / mcp_server.py / session.py 零改动。

## 5. 验收标准

- [x] 呼吸平滑（≥8fps 足够，周期 3.4s）

- [x] 光标 32px 真实 Win11 图形，尖端点命中坐标
- [x] 打字/操作全程**无黑框**

## 6. 遗留 & 未来方向

- `SetWindowCompositionAttribute` 真 acrylic 不可用于 ULW 窗口（DWM 冲突），本条为 Win32 平台硬限制，模拟方案即为终态；
- 帧率：scene 静止时纯光标移动可达 45fps+；呼吸重建 scene 约 11fps（全屏预乘是唯一热点，如需要可引 numpy 批量预乘提速）；
- MCP 工具集不变；`accent2` 已暴露给 AI（`session_start` 可传第二渐变色）。

（叠加层退出后屏幕与进入前逐像素一致，零残留；「右下角暗块」经双基线比对确认为泛光覆盖暖色壁纸时红通道下降的混合假象，非缺陷）。

### 7.1 四角黑色方框（抓屏实证）

用户反馈「屏幕 4 个角有黑色方块」。抓屏取证（`_diag_screen.py` 在演示各阶段对真实屏幕截图并统计四角像素）：

| 阶段 | 四角状态（修复前） |
|---|---|
| 会话稳定期 | 泛光正常渲染，四角边缘 14px 为亮色带（非黑） |
| 退出淡出期 | 泛光边框**变成不透明纯黑**：`glow_out` 分支执行 `rebuild_scene(mult*(1-t))` 只把 RGB 乘向 0，alpha 保持 255 —— 预乘域下 (0,0,0,255) 就是黑框，围绕全屏的 14px 边框闪黑，四个角最显眼 |
| 结束后 | 屏幕与壁纸一致，无残留 |

修复：

1. `rebuild_scene` 增加 `alpha_fade` 参数 —— 淡出改为衰减 **alpha**（`putalpha(A × (1-t))`），颜色保持不变，物理上不可能再出现黑框；
2. `_Win32Window` 首帧黑闪预防：创建后不再立即 `ShowWindow`，改为第一次 `UpdateLayeredWindow` 成功后由 `blit()` 再显示（layered 窗口在首次 ULW 前的背景未定义，可能整窗闪黑）。

回归证据（修复后抓屏）：退出淡出全程四角最小亮度 = 壁纸亮度（TL/TR/BL=39、BR=36），
**从未低于壁纸本身**，黑框归零；启动阶段 boot0 抓屏亦无黑闪。

### 7.2 四角「黑色方块」终局排查（2026-08-29，全流程真角实证）

用户持续反馈「屏幕四个角落还是有黑色方块，像渲染器问题」。此前诊断脚本采样的
是角部裁切的**内侧**像素（距屏幕边缘 ~90px），从未测过真正的屏幕角。本轮重写
采样（`_diag_exit_corners.py`），对**屏幕真角 14×14** 做了 pre → 启动 → 稳定 →
呼吸 → 退出 → 结束的全流程密集抓屏，并先用 `accent=#ffffff` 白框探针验证 ULW
管线 1:1 映射：

| 验证项 | 结果 |
|---|---|
| DIB 四角渲染 | 四角 alpha 0-234，可见像素亮度 204-234 ✓ |
| 白框探针（物理级校验） | 实测四角亮度与 `alpha=227*(1-i/14)^1.4` 模型逐行吻合（如 TR mean 87 vs 模型 ~85），**ULW 逐像素精确映射，无偏移/缩放** |
| 物理/虚拟分辨率 | 1920×1080 = 1920×1080，DPI 96（无缩放） |
| 全流程四角亮度 | 所有阶段四角 min 亮度**从未低于壁纸基线**（violations=none × 4 角） |
| 退出淡出 | exit2 起与壁纸逐帧一致，无黑框残留 |

**结论：DIB、ULW、屏幕显示三者逐像素一致，渲染器本身正确；但角部确有真实缺陷** ——
四条边的衰减 alpha 顺序覆写，角部重叠区只保留单条边贡献（`ramp[max(dx,dy)]`），
比相邻直段**暗约 2.6 倍**；叠加暗色壁纸/窗口的四角，「黑方块」由此而来。

修复：

1. **角部 alpha 覆写缺陷（真根因）**：四条边的衰减 alpha 原来画在同一张掩膜上顺序
   覆写，角部重叠区先画的边被后画的边覆盖，角部像素只取单条边贡献
   （`ramp[max(dx,dy)]`），角部整体比相邻直段**暗约 2.6 倍** —— 深色背景下四个角
   就是四块暗方块。改为每条边独立掩膜 + `ImageChops.lighter`（逐像素取最大）合成，
   角部 = 两条边泛光的**并集**，反转为比直段更亮的点；新增单测
   `test_build_glow_corner_brighter_than_band_run` 锁死该性质；
2. `_GLOW_THICK` 14 → **28px**、衰减指数 1.4 → **1.6**：亮带变宽变软，向内溶解进
   暗角而不是勾勒其轮廓；
3. `_GLOW_LO` 0.55 → 0.62：呼吸低谷时角部照明不再跌向暗区。

### 7.3 泛光融合为「长方体」（2026-08-29）

黑方块消失后用户反馈：「几个渐变要组成一个长方体，不要只画4条线」。上一版
（逐边色带 + 逐边 alpha 掩膜 `lighter` 合成）在数学上角部 alpha 已是并集，但
**颜色**仍按边独立填涂：四角重叠区保留最后绘制那条边的颜色，边与边交界处是
硬色缝，视觉上就是四条分离的线条。

修复：`_build_glow` 新增 numpy 路径（纯 PIL 旧路径保留为兜底）：

1. **alpha = 真距离场**：`d = min(x, y, W-1-x, H-1-y)`，`alpha = 255·mult·(1-d/thick)^1.6`
   （`d < thick`）——四边/四角由同一个连续函数生成，天然是一体的；
2. **颜色 = 周长连续采样**：每个像素按「最近屏幕边」的投影取周长渐变
   `c1→c2` 的颜色，且按 `(thick-d)²` 对各边加权混合——四角颜色从一条边**平滑
   流转**到下一条边，没有色缝；
3. `_GLOW_THICK` 28 → **40px**：更宽的柔和衰减让亮带读起来是「实心长方体」
   而非霓虹线。单测 `test_build_glow_corner_brighter_than_band_run` 继续通过
   （角部仍比直段亮，黑方块不回归）。
